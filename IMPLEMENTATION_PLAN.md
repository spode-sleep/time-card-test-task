# План реализации графика смен

## Цель и исходные материалы

Сделать работающее fullstack-приложение по макету Figma. Пользователь просматривает расписание сотрудников, назначает и редактирует смены несколькими способами, видит покрытие по датам и сохраняет результат в базе данных.

- [Задание и снимки макета](./figma-assignment.html).
- [Исходный макет Figma](https://www.figma.com/design/QVdDSEGTL1bWg7UmuPpoPe?node-id=0-1).
- Подтверждённые технологии — Vue 3 на клиенте и Node.js на сервере.
- Итоговые материалы по заданию — работающий сайт и репозиторий GitHub с исходным кодом.

При создании проекта выбрать совместимые стабильные версии, зафиксировать зависимости lock-файлом и указать поддерживаемую версию Node.js.

После каждого этапа проводить sanity check. Сверять результат с пунктами этапа, запускать относящиеся к изменениям проверки и проходить рабочий сценарий через обычную точку входа. Найденные ошибки исправлять перед завершением этапа, ограничения проверки фиксировать в плане.

## Рабочие допущения

Эти решения предложены для реализации. В исходном тексте они описаны неполно, поэтому их нужно сверить с доступными деталями Figma и требованиями вакансии.

- Одна ячейка соответствует одному сотруднику и одной календарной дате. В ячейке хранится одна смена, повторное назначение заменяет её.
- Дата смены — день её начала в часовом поясе организации. Для демо использовать Europe/Moscow и явно указать это в README.
- Время вводится с точностью до минуты. Окончание раньше начала означает переход на следующий день. Одинаковое время начала и окончания считать ошибкой.
- Быстрое назначение через заголовок даты открывает выбор шаблона. Предварительный вариант области назначения — сотрудники, видимые после поиска. Область действия должна быть явно показана в меню.
- Перетаскивание назначенной смены переносит её с сохранением времени. Если целевая ячейка занята, запросить подтверждение замены до изменения черновика.
- Кнопка «Сохранить» записывает черновик в БД. Предварительное поведение кнопки «Опубликовать» — сохранить текущий черновик и зафиксировать опубликованную версию расписания. До реализации этой кнопки проверить, ожидается ли от работодателя другая семантика.
- Покрытие — количество назначенных смен на дату среди всех сотрудников. Поиск по ФИО меняет видимые строки, значение покрытия остаётся общим для расписания.
